# Spec 001 — تشخیص کسره اضافه (ezafe)

## چرا
کسره اضافه معنای عبارت کلیدی فارسی را عوض می‌کند ولی معمولاً در متن نوشته نمی‌شود. بدون تشخیص، کلاسترینگ و QA نمایش ناقص می‌ماند. این برش فقط **تشخیص** را به `persian_seo_normalizer` اضافه می‌کند.

## چه چیزی (بدون تکنولوژی اجباری در سطح نیاز)
1. یک قابلیت عمومی برای تشخیص مواضع ezafe روی متن فارسی.
2. خروجی ساخت‌یافته (نه فقط bool سراسری) تا مصرف‌کننده بداند روی کدام توکن/بازه علامت هست.
3. پکیج پایه بدون وابستگی سنگین NLP قابل import و تست بماند.
4. اگر backend NLP در دسترس نباشد: رفتار تعریف‌شده با پیام خطای واضح.
5. قاعده دوفرمی حفظ شود: این قابلیت به دامنهٔ نمایش/تشخیص تعلق دارد؛ `analyze_form` و fingerprint نباید به وجود ezafe وابسته شوند (اعراب از قبل در `unify_characters` حذف می‌شود).
6. هر تبدیلی که متن را تغییر دهد باید idempotent باشد: `f(f(x)) == f(x)`.

## خارج از حوزه
- سرویس API، داکر، وردپرس، Railway
- ادغام اجباری داخل `display_form` در همین برش (ممکن است در برش بعد)
- تغییر اسکیمای دیتابیس
- MCP tool جدید (بعد از پایدار شدن تابع)

## معیار پذیرش
- تابع عمومی مستند و exportشده از پکیج
- تست‌های واحد برای مسیر موجود بودن و نبودن backend
- ۳۶ تست موجود همچنان سبز
- کیس‌های شرور فارسی طبق اسکیل normalization
