# ADR-0002 — DadmaTools به‌عنوان backend تشخیص ezafe

**وضعیت:** پذیرفته‌شده (لایسنس تأیید شد؛ پیاده‌سازی پس از تأیید پلن برش)

## زمینه
تشخیص کسره اضافه برای سئوی فارسی لازم است و در خط فارسی معمولاً نوشته نمی‌شود.

جایگزین لازم نشد — Apache-2.0 برای مسیر تجاری ما کافی است.

## تصمیم
- پکیج پایه بدون DadmaTools سبک می‌ماند.
- وابستگی فقط از مسیر موجود: `optional-dependencies.nlp` با **پین دقیق**
  `dadmatools==2.3.6` (خروجی مدل بین نسخه‌ها پایدار بماند).
- تابع عمومی پایدار است؛ پیاده‌سازی پشت Protocol قابل تعویض.
- **import تنبل:** `dadmatools` فقط داخل `DadmaEzafeBackend.detect`؛
  import سطح ماژول ممنوع تا torch با import پکیج پایه کشیده نشود.
- بدون نصب extras: خطای روشن (`EzafeBackendUnavailable`).

## پیامد
- تست‌های پایه و CI بدون دانلود مدل DadmaTools سبز می‌مانند (mock / نبود backend).
- تست یکپارچگی واقعی با DadmaTools با `skipUnless` علامت‌گذاری می‌شود و فقط وقتی extras نصب است اجرا می‌گردد.

## ریسک‌های عملیاتی (ثبت‌شده؛ راه‌حل کامل موکول)
1. **دانلود مدل در اولین استفاده:** DadmaTools مدل‌ها را در runtime از شبکه می‌گیرد، نه فقط هنگام `pip install`. محیط اجرا باید به اینترنت (یا کش از پیش آماده‌شده) دسترسی داشته باشد. برای سرویسی که ممکن است داخل ایران اجرا شود این محدودیت واقعی است. راه‌حل‌های محتمل بعداً: vendoring/کش مدل در ایمیج، آینه داخلی، یا backend جایگزین بدون دانلود runtime.
2. **حجم torch:** وابستگی torch ایمیج دپلوی را چند گیگابایت سنگین می‌کند. انتخاب extras اختیاری درست بود؛ پیامد: سرویس‌های production که ezafe لازم ندارند نباید `[nlp]` را در ایمیج پایه بکشند — ایمیج/ورکر جدا یا نصب شرطی.
