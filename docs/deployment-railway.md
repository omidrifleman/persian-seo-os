# اجرا روی Railway

## تقسیم کار — مهم‌ترین نکته این فایل

Railway جایگزین سیستم توسعه نیست. جایگزین Docker است.

| کار | کجا |
|---|---|
| نوشتن کد، Cursor، اسکیل‌ها، spec-kit، گیت | سیستم خودت (لوکال) |
| اجرای تست‌های لایه نرمال‌سازی | سیستم خودت (فقط پایتون) |
| Postgres و Redis | Railway |
| API، ورکرها، زمان‌بند | Railway (بعداً، وقتی نوشته شدند) |

Cursor روی سیستم خودت اجرا می‌شود و فایل‌های لوکال را می‌خواند. پس Git، Python و Node لوکال همچنان لازم‌اند (ببین `scripts/bootstrap-windows.ps1`).
اما **Docker، Postgres و Redis لوکال دیگر لازم نیستند** — و این برد بزرگی است، چون روی ویندوز خام Docker Desktop پردردترین قسمت نصب است.

## وضعیت فعلی پروژه

الان هیچ سرویس HTTP قابل دپلوی وجود ندارد. پکیج فعلی شامل این‌هاست:
- کتابخانه `persian_seo_normalizer` (کتابخانه، نه سرویس)
- اسکلت `services/mcp_server` و `services/llm_gateway` (بدون ورودی وب)
- مایگریشن `db/migrations/0001_init.sql`

پس تنها کار مفید امروز روی Railway: **بالا آوردن Postgres و اجرای مایگریشن.**
دپلوی کد را بگذار برای وقتی که `services/api` وجود داشته باشد.

## مرحله ۱ — ساخت پروژه و Postgres (بدون CLI)

در داشبورد Railway:

1. `New Project` → `Empty Project`
2. نامش را بگذار `persian-seo-os`
3. در همان پروژه: `+ Create` → `Database` → `Add PostgreSQL`
4. روی سرویس Postgres کلیک کن → تب `Variables` → مقدار `DATABASE_PUBLIC_URL` را کپی کن

تفاوت مهم و رایج‌ترین اشتباه تازه‌کارها:

| متغیر | کجا کار می‌کند |
|---|---|
| `DATABASE_URL` | فقط از داخل شبکه خود Railway (`*.railway.internal`، IPv6) |
| `DATABASE_PUBLIC_URL` | از لپتاپ خودت — برای توسعه لوکال این را بگیر |

اگر `DATABASE_URL` را در `.env` لوکال بگذاری، اتصال با خطای گیج‌کننده DNS رد می‌شود.

## مرحله ۲ — اجرای مایگریشن (بدون نصب psql)

روی سرویس Postgres در داشبورد، تب `Data` یا `Query` را باز کن.
محتوای کامل `db/migrations/0001_init.sql` را پیست کن و اجرا بزن.

بعد از اجرا، این دو را تأیید کن — قلب معماری ایمنی ما همین دو موردند:

```sql
-- باید approval_id را NOT NULL نشان بدهد
SELECT column_name, is_nullable
FROM information_schema.columns
WHERE table_name = 'publish_jobs' AND column_name = 'approval_id';

-- باید رد شود: انتشار بدون تأیید انسانی غیرممکن است
INSERT INTO publish_jobs (id) VALUES (gen_random_uuid());
```

خط دوم باید خطای null value in column "approval_id" بدهد.
اگر این خطا را نداد، گیت تأیید انسانی شکسته است و نباید جلوتر بروی.

## مرحله ۳ — وصل کردن محیط لوکال

فایل `.env.example` را به `.env` کپی کن و فقط این دو خط را عوض کن:

```
DATABASE_URL=<مقدار DATABASE_PUBLIC_URL از Railway>
REDIS_URL=<مقدار REDIS_PUBLIC_URL از Railway، اگر Redis ساختی>
```

`.env` در `.gitignore` هست. هرگز کامیتش نکن — این رشته اتصال شامل رمز دیتابیس است.

`PUBLISH_DRY_RUN=true` را دست نزن.

## مرحله ۴ — دپلوی کد (بعداً)

وقتی اولین سرویس HTTP را نوشتیم:

1. مخزن را به GitHub پوش کن (خصوصی)
2. در Railway: `+ Create` → `GitHub Repo` → مخزن را انتخاب کن
3. `railway.json.example` را به `railway.json` تغییر نام بده و `startCommand` را درست کن
4. در تب Variables سرویس، از مرجع متغیر استفاده کن نه کپی دستی:
   `DATABASE_URL=${{Postgres.DATABASE_URL}}`

این‌جا نسخه internal درست است، چون سرویس داخل شبکه Railway اجرا می‌شود.

## هشدارها

**ترافیک روز اول را خرج نکن.** دوره رایگان ۳۰ روزه و ۵ دلار است؛ بعد از آن طرح Free فقط ۱ دلار در ماه اعتبار می‌دهد و رول نمی‌شود. در دوره آزمایشی سقف ۱ گیگ رم و ۵ سرویس در هر پروژه است. یک Postgres کوچک ماه‌ها دوام می‌آورد؛ یک کراولر رهاشده در چند روز اعتبار را می‌بلعد.

**داده طرح رایگان پاک می‌شود.** ۳۰ روز پس از انقضا، دیتابیس حذف می‌شود. تا وقتی مشترک نشده‌ای، این دیتابیس را دورریختنی بدان و مایگریشن‌ها را مرجع حقیقت بدان.

**پرداخت.** Railway برای اشتراک فقط کارت اعتباری می‌پذیرد. کارت ایرانی کار نمی‌کند. این را قبل از وابستگی معماری حل کن، نه بعد.

**Railway CLI روی ویندوز بومی نیست** — مستندات رسمی WSL می‌خواهند. برای همه مراحل بالا به CLI نیازی نیست؛ داشبورد وب کافی است. تا زمانی که واقعاً لازم نشده، WSL نصب نکن.
